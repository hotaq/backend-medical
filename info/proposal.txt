### **เอกสารสรุปโครงการ (Project Proposal & Status Report): Triage-BOTS**

**วันที่:** 20 กรกฎาคม 2568
**เวอร์ชัน:** 1.0

#### **1. ภาพรวมโครงการ (Executive Summary)**

**Triage-BOTS** คือระบบปัญญาประดิษฐ์อัจฉริยะที่ถูกออกแบบมาเพื่อช่วยแก้ไขปัญหา "คอขวด" ในระบบสาธารณสุข โดยทำหน้าที่เป็น **"ระบบจัดลำดับคิวอัจฉริยะ (Intelligent Triage & Prioritization System)"** สำหรับผู้ป่วยที่รอคิวพบแพทย์เฉพาะทาง ระบบจะทำการวิเคราะห์ข้อมูลของผู้ป่วยแบบองค์รวม (อาการ, ผลตรวจ, ประวัติ, ภาพถ่ายทางการแพทย์) เพื่อประเมินระดับความเร่งด่วนของแต่ละเคส และจัดลำดับคิวการนัดหมายใหม่โดยอัตโนมัติ เพื่อให้มั่นใจว่า **ผู้ป่วยที่มีอาการน่าเป็นห่วงและมีความเสี่ยงสูงสุด จะได้รับการตรวจรักษาก่อน**

---

#### **2. ปัญหาที่ต้องการแก้ไข (Problem Statement)**

ปัจจุบัน ระบบการนัดหมายแพทย์เฉพาะทางส่วนใหญ่ยังคงเป็นแบบ "ใครมาก่อนได้ก่อน" (First-Come, First-Served) ซึ่งก่อให้เกิดปัญหาสำคัญ 3 ประการ:
1.  **การรอคอยที่ยาวนาน:** ทรัพยากรแพทย์เฉพาะทางมีจำกัด ทำให้ผู้ป่วยทุกคนต้องรอคิวนานโดยไม่คำนึงถึงความรุนแรงของโรค
2.  **ความเสี่ยงที่มองไม่เห็น (Hidden Risk):** ผู้ป่วยที่มีอาการดูไม่รุนแรงภายนอก แต่มีปัจจัยเสี่ยงซ่อนอยู่ในผลเลือดหรือประวัติ อาจถูกจัดอยู่ในคิวท้ายๆ ทำให้การวินิจฉัยล่าช้าและผลการรักษาแย่ลง
3.  **ภาระงานของบุคลากร:** การคัดกรองและจัดลำดับความสำคัญด้วยมนุษย์เป็นกระบวนการที่ใช้เวลาและอาจเกิดความคลาดเคลื่อนได้

---

#### **3. โซลูชันที่นำเสนอ (Proposed Solution)**

เรากำลังสร้างแพลตฟอร์มที่ให้แพทย์หรือบุคลากรทางการแพทย์สามารถป้อนข้อมูลของผู้ป่วยเข้ามาในระบบ จากนั้น Triage-BOTS จะใช้สถาปัตยกรรม AI ขั้นสูงแบบ **"Mixture of Experts"** เพื่อ:
1.  **วิเคราะห์ข้อมูลแบบหลายมิติ (Multi-modal Analysis):** ทำความเข้าใจข้อมูลทั้งในรูปแบบข้อความ (อาการ, ประวัติ), ตัวเลข (ผลเลือด), และรูปภาพ (ภาพถ่ายจอประสาทตา, CT Scan)
2.  **ประเมินคะแนนความเสี่ยง (AI-Powered Risk Scoring):** ใช้โมเดล Machine Learning เฉพาะทาง (ML Tools) เพื่อประเมินความเสี่ยงของโรคต่างๆ ที่เกี่ยวข้อง และให้คะแนนความเร่งด่วน (Triage Score) ที่เป็นกลางและมีมาตรฐาน
3.  **จัดลำดับคิวแบบไดนามิก (Dynamic Prioritization):** นำ Triage Score มาจัดเรียงลำดับคิวผู้ป่วยใหม่ทั้งหมด เพื่อให้โรงพยาบาลสามารถเรียกผู้ป่วยที่มีความเสี่ยงสูงสุดมาพบแพทย์ได้ก่อน

---

#### **4. สถาปัตยกรรมของระบบ (System Architecture)**

ระบบใช้สถาปัตยกรรมแบบ **"Agent with ML Tools"** ซึ่งประกอบด้วย:

* **🧠 Chief-BOT (Orchestrator):**
    * **เทคโนโลยี:** Large Language Model (LLM) เช่น `google/medgemma`
    * **หน้าที่:** เป็น "ผู้จัดการ" หลัก ทำหน้าที่วิเคราะห์ข้อมูลที่ผู้ใช้ป้อนเข้ามาทั้งหมด เพื่อทำความเข้าใจบริบท และ "เลือก" ว่าจะส่งต่องานไปให้ "ผู้เชี่ยวชาญ" หรือ ML Tool ตัวไหนที่เหมาะสมที่สุด

* **⚙️ ML Tools (Specialized Experts):**
    * เป็นโมเดล Machine Learning ที่ถูกฝึกมาเพื่องานใดงานหนึ่งโดยเฉพาะ มีความแม่นยำสูง
    * **ตัวอย่าง Tools:**
        * **Vision-BOT (Diabetic Retinopathy Tool):** วิเคราะห์ภาพถ่ายจอประสาทตา (โมเดล CNN: ResNet/EfficientNet)
        * **Heart Disease Prediction Tool:** ทำนายความเสี่ยงโรคหัวใจจากข้อมูลผลเลือดและประวัติ (โมเดล Scikit-learn: RandomForest/XGBoost)
        * **CKD Prediction Tool:** ทำนายความเสี่ยงโรคไตเรื้อรังจากผล Lab (โมเดล Scikit-learn)

* **🗣️ Synthesizer:**
    * **เทคโนโลยี:** ใช้ Chief-BOT (LLM) อีกครั้งในตอนท้าย
    * **หน้าที่:** นำผลลัพธ์ที่เป็นข้อมูลดิบทางเทคนิคจาก ML Tools (เช่น `risk_score: 0.87`) มาเรียบเรียงและ "อธิบาย" เป็นภาษาที่มนุษย์เข้าใจง่าย ให้คำแนะนำที่เป็นประโยชน์และมีความเห็นอกเห็นใจ

#### **5. แผนการพัฒนาและสถานะปัจจุบัน (Development Plan & Status)**

เราได้วางแผนการพัฒนาออกเป็น 4 ระดับ และนี่คือสถานะล่าสุด:

* **LEVEL 1: พื้นฐาน - การพิสูจน์แนวคิด (Proof of Concept)**
    * **เป้าหมาย:** พิสูจน์ว่าโมเดลหลัก (Vision-BOT) ทำงานได้
    * **สถานะ:** ✅ **เสร็จสิ้น** (สามารถสร้างโมเดลวิเคราะห์โรคตาจากภาพใน Notebook ได้)

* **LEVEL 2: ต้นแบบที่ทำงานได้ (Functional Prototype)**
    * **เป้าหมาย:** สร้างเว็บแอปฯ ง่ายๆ ที่ให้ผู้ใช้อัปโหลดภาพและเห็นผลลัพธ์
    * **สถานะ:** ✅ **เสร็จสิ้น** (มี Backend FastAPI และ Frontend พื้นฐานที่เชื่อมต่อกันได้)

* **LEVEL 3: ระบบที่เชื่อมต่อกัน (Integrated System - MVP)**
    * **เป้าหมาย:** ทำให้แนวคิด "Agent with Tools" เกิดขึ้นจริง มีระบบจัดการเคสเบื้องต้น
    * **สถานะ:** ⌛️ **กำลังดำเนินการ (In Progress)**
        * **Backend:**
            * ✅ สร้าง API ด้วย FastAPI พร้อมระบบจัดการผู้ป่วยและฐานข้อมูล (SQLite)
            * ✅ พัฒนา Class สำหรับ `TextBOT` (LLM Agent) และ `VisionBOT`
            * ✅ แก้ไขปัญหาด้านความปลอดภัย (ใช้ Passlib เข้ารหัส) และประสิทธิภาพ (วางแผนใช้ `run_in_threadpool` สำหรับ I/O)
            * ⌛️ **กำลังดำเนินการ:** ปรับปรุงสถาปัตยกรรมเพื่อรองรับการเรียกใช้ ML Tools หลายๆ ตัวตามที่ออกแบบไว้
        * **Frontend:**
            * ✅ สร้างหน้า Dashboard สำหรับแพทย์ด้วย React.js
            * ✅ มีฟังก์ชันล็อกอิน, ค้นหาผู้ป่วย, และฟอร์มสำหรับส่งข้อมูล (อาการและรูปภาพ)
            * ✅ สามารถแสดงผลการวิเคราะห์เบื้องต้นได้

* **LEVEL 4: แพลตฟอร์มที่พร้อมขยายผล (Scalable Platform)**
    * **เป้าหมาย:** เตรียมระบบให้พร้อมใช้จริง, ปลอดภัยสูง, รองรับผู้ใช้จำนวนมาก
    * **สถานะ:** 📝 **วางแผนสำหรับอนาคต** (แนวทาง: เปลี่ยน DB เป็น PostgreSQL, ใช้ Microservices และ Docker)
